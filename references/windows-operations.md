# Windows后台操作、Custom与本地游戏导入

## 操作边界

优先文件/CLI/原生接口和离屏渲染。不要系统鼠标/全局键盘、切焦点、关闭用户窗口、替用户保存未保存工程或启动游戏。必要的新辅助进程必须隐藏/不激活。用户说自己查看时，止于文件写入与读回。

FLS默认使用用户指定/本机配置的1.3.0。核验**实际进程ExecutablePath**，不能用文件关联或另一个后台实例证明用户正用的版本。来源不明的旧版不能偷偷当默认。

## Custom导入：为何仅写注册表不够

Windows脚本与Explorer启动的FLS可能处于不同的配置视图。曾出现脚本读回有条目，用户多次重开仍看不到。可靠路径是在**实际用户FLS进程上下文**中读取/写入指定Custom值；FLS关闭时可在其真实Explorer启动上下文处理，不依赖另起一个脚本进程的HKCU视图。

本项目适配器通过限定的Frida RPC调用进程自己的注册表API，仅操作 `Software\ForzaTools\ForzaLiveryStudio\shapes` 的 `customGroups`。不是游戏内存注入，不写当前编辑工程。桥接不提供启动/关闭窗口的接口。

Qt值必须保持带类型的 `@ByteArray(<JSON>)` 序列化；不能把看似一样的普通字符串、另一套库或旧QSettings路径当作成功。对同版本按实际已验证格式处理，不据此推断任意FLS版本都兼容。

步骤：

1. 根据进程路径和用户会话确定实际PID；只读快照并备份已有列表。
2. 验证输入为独立贴纸`.3so`、SHA和实际层数；以稳定ID追加。明确要求替换时只更新目标ID；保留所有其他项。
3. CAS写入：若从读取后列表被用户/其他任务改变，拒绝覆盖，重新读取合并。
4. 在同一实际上下文读回完整数据，检查所有非目标项未变。
5. FLS通常在启动时加载列表。告知用户方便时保存并重开，再搜索简短唯一名；不替其关闭。读回成功与用户面板可见确认分别记录。
6. 未显示时继续查真实进程/视图/格式，不能反复说“导入成功，你再重开”。

示例 jobs JSON 是数组，每项 `project`、`name` 和可选 `id`；替换使用明确 `replaceId`。执行：

```text
python scripts/custom.py --profile <本机配置> --jobs <本任务jobs.json> --pid <实际用户PID> --output <新记录目录>
python scripts/custom.py --profile <本机配置> --jobs <本任务jobs.json> --pid <实际用户PID> --output <另一新记录目录> --apply
```

已授权替换时再加 `--replace-authorized`。此技术标志不自行产生授权。测试可使用带专用marker的 `--sandbox-library` 文件，输出明确标记为隔离测试，不能当用户真实面板可见证据。

## .3so与游戏原生资产

`.3so` 是编辑工程，不是可直接移动到游戏目录即能识别的原生存档。完整整车需导出匹配的私人 `C_livery` 和 `header`，可附菜单缩略图。贴纸工程不能冒充完整整车。源数据与原生计数、车型、材质描述均需读回一致。

已有正确FLS原生导出可直接用Workbench整理。对于本技能创建的source-less矢量工程，可用 `native.py export`，重用已验证编解码器/图层编码器；不支持的raster、mask、组透明度或带源前缀工程应停在明确错误处，不静默丢数据。编辑面保存带来的visible标记不得用于删除其他面。

导出需要用户自己的合法未发布身份header，不能使用下载作品的作者身份。实际日志只记指纹/哈希，不公开原生身份字节。公开包不含身份文件。隔离测试使用合成身份，不可导入真实游戏。

```text
python scripts/native.py --profile <本机配置> export --input <整车.3so> --seed-header <用户自己的header> --output <新导出目录> --thumbnail <已有实车图>
```

导出本身不写游戏、不需要开游戏。菜单缩略图可复用旧图，但必须说明不代表新一轮视觉检查。

## 用户要求导入本地游戏

1. 确认请求已授权本地导入；游戏须关闭。运行中就继续做离线准备，写入前让用户退出，不能强关游戏。
2. 发现当前活动PGS `current/ContainersRoot` 的实际快照，不能硬编码上轮数字目录。Steam等其他格式走其已验证适配器，不能套用PGS目录。
3. 验证完整私人资产、车型和层数；按下面的项目级滚动策略完整备份活动存档，校验每一文件后才写入。
4. 默认追加新项：新目标不得已存在，临时目录写入→哈希回读→原子改名。写入前后复核活动快照未变，旧文件哈希全部不变。
5. 用户明确说“删上次换这次”时，只定位上次回执中那一项，备份后以精确路径移除；保留用户原件、历史归档及其他涂装。不能删同车型所有作品。
6. 原始`.3so`哈希未变，所有原存档和新增原生文件完整读回、活动根未变，并记录本地导入回执。成功后才淘汰旧完整备份。用户负责在游戏中应用/保存/发布。

`native.py install --ready ... --output ... --project-root <共同项目根> --authorized-note <本次用户要求的简要记录>` 提供追加路径。测试使用 `--sandbox-root`，要求其 `.livery-workflow-sandbox.json` 为 `kind=livery-workflow-isolated-import-test` 且存在 `current/ContainersRoot`；只为防止边界重合检查真实存档的位置，不读取其美术内容、不写真实游戏存档。

隔离测试根与该次安装证据目录应为同一试验目录下的兄弟目录，并拒绝与任何真实存档账户树相交。确认这一边界后，测试调用可在用户游戏运行时执行；只对这些隔离调用临时替换进程检查，调用结束恢复。正式导入的关闭游戏检查保持有效，不能用测试marker指向真实存档来绕过它。

替换的移除步骤须先核验解析后的绝对路径为活动根的**直接子目录**、旧basename/车型/哈希匹配回执、无重解析点、备份可还原、新项已验证，再用PowerShell `Remove-Item -LiteralPath <精确旧项> -Recurse`。不强删占用文件，不通过跨shell拼接删除。

## 完整存档备份：整个项目滚动保留一份

这是跨车型、跨子任务的项目规则，也适用于其他电脑。完整快照不能继续分散为“每次任务各留一份”。本项目默认**只保留最近一次成功导入前的一份完整存档备份**；清单、导入日志、核验记录长期保留。用户未报告损坏，视上次导入正常，不重复询问。

1. 为整个项目选择一个共同根，不能位于实际存档内。`native.py` 优先取 `--project-root`，其次私有配置 `backupPolicyRoot`，再次当前工作目录。始终给自动化任务配置共同根，不能每次把新子目录当项目。Workbench可用 `--project-root`、上级策略标记或 `settings.local.json` 的 `backup_policy_root`。
2. 根中保存 `.livery-backup-policy.json`；`.livery-save-backups/archives/` 放完整ZIP，`state.json` 登记所有历史和异常，`records/` 保存精确删除计划和回执。每次任务自己的目录仍保留清单/导入日志。项目移动后先迁移并核验登记的绝对路径，不猜路径删除。
3. 创建新完整备份，检查ZIP CRC、压缩包SHA-256、精确成员集合、大小及**每一成员内容SHA-256**。旧备份此时仍保留。备份期间、写入前再比较源存档，发生变化则拒绝写入并保留备份。
4. 新涂装写入后核验所有原文件未变、新文件全数正确、没有额外增删且活动根稳定。适配器完成自己的读回后，才调用 `finish_import`。它再次完整验证要保留的新备份，之后删除上次及更早正常完整ZIP。Windows删除只用随包的精确路径PowerShell助手；不强删被占用文件。清理失败记为待处理，不能误报为游戏导入失败。
5. **用户报告损坏或本次导入失败**：立即登记 hold，保留相关备份；先诊断/恢复/核验，记录处理结果再解除 hold。解除本身不删除，须后续成功导入或核验后执行清理。不能仅因一次后续导入成功就自动忽略尚未解决的损坏报告。
6. 历史分散备份首次接入时先盘点、核验并登记。用户未报告损坏且正常导入有记录时可按当前授权采用，不重复确认；再保留最新可用一份。最新备份此前已被明确删除时，应注明当前保留的是最新**现存**备份，不能伪称已补回最近导入前状态。

维护命令（无需启动GUI）：

```text
python -m fh6_livery_workbench.backup_retention --project-root <共同项目根> status
python -m fh6_livery_workbench.backup_retention --project-root <共同项目根> hold --reason <用户报告或失败事实>
python -m fh6_livery_workbench.backup_retention --project-root <共同项目根> resolve --resolution <已处理及核验结果>
python -m fh6_livery_workbench.backup_retention --project-root <共同项目根> prune
```

最后一条只清理已正常完成/已处理失败的旧完整ZIP；未解决事件、待完成备份不会被静默删除。实际存档、输入母稿、`.3so`成品、逐项替换回滚材料、清单和日志不是完整快照淘汰对象。隔离测试有自己的策略根与合成数据，绝不使用生产项目的备份登记。

## 交付与发布

按既有中文素材库追加工程、母稿、参数和证据。用户名、分享代码、分类用本任务要求；常见“卡通／角色”不是所有任务的默认授权。AI不将本地文件导入冒充线上发布。

用户：进入游戏应用该涂装→涂装页面保存→发布→下载/应用核查。用户可在任何一步提出修改、层数调整或重新导入；原件及已接受版本保留。
